# Messenger

Веб-приложение мессенджера, реализованное в рамках 2-го спринта Яндекс Практикума.

## Описание

Приложение представляет собой клиентскую часть мессенджера с следующими возможностями:

- **Авторизация и регистрация** — страницы входа и регистрации с валидацией форм
- **Список чатов** — отображение списка чатов с последними сообщениями
- **Чат** — отправка и получение сообщений в реальном времени
- **Профиль пользователя** — просмотр и редактирование данных профиля
- **Настройки** — изменение пароля

## Технологии

- **Vite** — сборщик и dev-сервер
- **TypeScript** — строгая типизация
- **ESLint** — линтер для JavaScript/TypeScript
- **Stylelint** — линтер для CSS
- **XHR (XMLHttpRequest)** — HTTP-клиент на нативном XHR без использования fetch/axios
- **EventBus** — система событий для компонентов
- **Block** — базовый класс для компонентов с жизненным циклом
- **Шаблонизатор** — простой шаблонизатор на template literals

## Архитектура

Проект следует архитектуре MVC и компонентному подходу:

```
src/
├── core/           # Базовые классы (Block, EventBus, View)
├── pages/          # Страницы приложения (Login, Register, Chats, Profile, Settings)
├── components/     # Переиспользуемые компоненты (Button, Input, Form, Message)
├── services/       # Сервисы (HTTPTransport)
├── utils/         # Утилиты (validation, template)
├── types/         # TypeScript типы и интерфейсы
├── styles/        # Глобальные стили
└── controllers/   # Контроллеры (AppController - устарел, используется роутер в main.ts)
```

## Функциональность

### Навигация

Роутинг реализован на событиях без использования внешних библиотек:

- Переход по ссылкам с атрибутом `data-link`
- Поддержка истории браузера (back/forward)
- Автоматический рендеринг страниц при изменении URL

### Валидация форм

Единая система валидации для всех форм:

- Валидация на событие `blur` для каждого поля
- Повторная валидация при отправке формы (`submit`)
- Отображение ошибок под полями
- Блокировка кнопки отправки при наличии ошибок
- Логирование данных формы в консоль при успешной валидации

Поддерживаемые поля:
- `first_name`, `second_name` — имя и фамилия
- `login` — логин (3-20 символов, латиница)
- `email` — email адрес
- `password` — пароль (8-40 символов, заглавная буква и цифра)
- `phone` — телефон (10-15 цифр)
- `message` — сообщение (не пустое)

### HTTP-клиент

Класс `HTTPTransport` реализует HTTP-запросы через XHR:

- Методы: `get`, `post`, `put`, `delete`
- Поддержка query string для GET-запросов
- JSON body для POST/PUT/DELETE
- Поддержка FormData
- Обработка ошибок и таймаутов
- Парсинг JSON-ответов

### Компоненты

Базовые переиспользуемые компоненты:

- **Button** — кнопка с различными стилями
- **Input** — поле ввода с валидацией
- **Form** — форма с автоматической валидацией
- **Message** — отображение сообщения в чате

## Установка и запуск

### Требования

- Node.js 18+
- npm или yarn

### Установка зависимостей

```bash
npm install
```

### Запуск в режиме разработки

```bash
npm run dev
```

Приложение будет доступно по адресу `http://localhost:5173`

### Сборка для продакшена

```bash
npm run build
```

Собранные файлы будут в папке `dist/`

### Превью продакшен-сборки

```bash
npm run preview
```

### Проверка типов

```bash
npm run typecheck
```

### Линтинг

```bash
# Проверка TypeScript/JavaScript
npm run lint

# Проверка CSS
npm run stylelint
```

## Структура страниц

### `/login` — Вход

Форма входа с полями:
- Логин
- Пароль

Ссылка на регистрацию (`/register`)

### `/register` — Регистрация

Форма регистрации с полями:
- Имя
- Фамилия
- Логин
- Email
- Пароль
- Телефон

Ссылка на вход (`/login`)

### `/chats` — Список чатов

- Список чатов слева
- Область сообщений справа
- Форма отправки сообщения
- Возможность создания новых чатов
- Групповые сообщения

### `/profile` — Профиль

Форма редактирования профиля:
- Email
- Логин
- Имя
- Фамилия
- Телефон

Ссылка на чаты (`/chats`)

### `/settings` — Настройки

Форма смены пароля:
- Старый пароль
- Новый пароль


## Особенности реализации
1. **Клиентская генерация** — все страницы генерируются на клиенте
2. **Компонентный подход** — использование класса `Block` с жизненным циклом
3. **EventBus** — система событий для коммуникации между компонентами
4. **Строгая типизация** — полная типизация на TypeScript
5. **Валидация** — единая система валидации для всех форм
6. **XHR вместо fetch** — использование нативного XMLHttpRequest
